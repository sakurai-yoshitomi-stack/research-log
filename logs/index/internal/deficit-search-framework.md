# 不足探索モデル / Deficit Search Framework

更新日: 2026-09-19

## 1. 基本思想

人は検索語そのものを探しているのではなく、自分の中にある「不足」を埋めようとしている。
検索語は、その不足が具体化・対象化されていく途中で表面化した表現である。

例:

```
なんか腹減った
→ 何か食べたい
→ ランチ
→ 麺
→ 油そば
→ 仙台 油そば
→ 麺屋政宗 油そば
```

この連鎖を、単なる関連キーワードの集合ではなく、
**不足が曖昧状態から対象確定へ移る認知的探索過程**
として扱う。

---

## 2. 探索レベル

| Level | 状態 | 例 |
|---|---|---|
| L0 | 感覚的不足 | 腹減った |
| L1 | 欲求 | 何か食べたい |
| L2 | 行動・目的 | ランチしたい |
| L3 | カテゴリ | 麺、カレー、そば |
| L4 | 対象 | 油そば |
| L5 | 条件付与 | 仙台 油そば |
| L6 | 固有対象 | 麺屋政宗 油そば |

探索は必ずL0から始まるとは限らない。
利用者は任意のレベルから探索を開始できる。

---

## 3. Deficit Search Tree（DST）

1つの検索語・実績語を中心ノードとして、AIが3方向に展開する。

### 上方向
親概念・上位不足へ戻す。

例:

```
麺屋政宗 油そば
→ 仙台 油そば
→ 油そば
→ 麺
→ ランチ
→ 何か食べたい
```

### 横方向
代替候補・隣接カテゴリへ広げる。

例:

```
油そば
├─ まぜそば
├─ ラーメン
├─ つけ麺
└─ 汁なし麺
```

### 下方向
条件・用途・固有名詞へ具体化する。

例:

```
油そば
→ 仙台 油そば
→ 仙台駅 油そば
→ 麺屋政宗
→ 麺屋政宗 油そば
→ 麺屋政宗 油そば 値段
```

---

## 4. 実測検索語を中心に置く

AIだけでキーワードを生成しない。

YouTube Studio、Google Search Console、サイト内検索、SNS、EC、検索ログ等から、
**実際に流入・反応が発生した語を「観測済みノード」として登録する。**

実例:

- 湾岸ミッドナイト
- 湾岸ミッドナイト 6RR PLUS
- 麺屋政宗 油そば

観測済みノードを起点に、AIが親・子・横枝を推定する。

運用サイクル:

```
仮説
→ コンテンツ生成
→ 公開
→ 検索・流入データ取得
→ 観測済みノード登録
→ DST更新
→ 次の仮説
```

---

## 5. ノード属性

各ノードには検索語だけでなく実績値を持たせる。

候補属性:

- 検索流入数
- 再生数 / PV
- CTR
- 視聴維持率 / 滞在時間
- 公開からの経過日数
- 継続流入の有無
- 関連動画・関連記事流入
- 検索語一致度
- コンバージョン
- 新規 / 既存
- 流入元
- 観測日

これによりAIが枝ごとの強弱を判断できる。

---

## 6. Flow / Stock 判定

コンテンツを2種類に分ける。

### Flow
公開直後の配信・推薦で消費され、時間経過で流入が急減するもの。

### Stock
公開後に時間が経っても、検索・関連・参照から継続的に拾われるもの。

ストック候補判定の考え方:

- 公開後一定期間を超えても継続流入がある
- 検索流入または関連流入が存在する
- 48時間・7日・28日など複数窓で完全停止していない
- 単発バズではなく小さな再生・閲覧が継続する

総再生数だけで価値を判断しない。
**小さくても持続する流入を別軸で評価する。**

---

## 7. AI処理フロー

### INPUT
- 検索語
- アクセスログ
- 動画タイトル
- 記事タイトル
- 検索流入語
- 商品名
- ユーザー質問
- 過去コンテンツ

### PROCESS

1. 不足推定  
   「この検索の背景で、何が足りていないのか」を推定

2. 探索レベル判定  
   L0〜L6へ分類

3. ツリー生成  
   親・横・子ノードを生成

4. 実績付与  
   再生数、PV、CTR等を付与

5. 枝の強弱判定  
   強い枝、弱い枝、未開拓枝を識別

6. コンテンツ候補生成  
   動画、記事、商品、研究、FAQ等へ展開

7. 公開

8. 実データ回収

9. DST更新

---

## 8. コンテンツ生成への適用

1つの強い検索語から、探索レベル別に複数コンテンツを生成する。

例: 「麺屋政宗 油そば」

- 上位不足向け  
  「仙台で何食べる？」
- 中位カテゴリ向け  
  「仙台で油そば」
- 固有対象向け  
  「麺屋政宗の油そば」
- 確認探索向け  
  「麺屋政宗の油そば、実際どう？」

同じ題材を、異なる探索レベルに合わせて再構成できる。

## 9. 適用範囲

### YouTube
検索語 → タイトル → 説明 → ハッシュタグ → 次動画企画

### note / Blog
検索意図 → 記事テーマ → 見出し → 関連記事

### Webサイト
検索流入 → コンテンツクラスタ → 内部リンク → FAQ

### OJISAN SOUNDS
音の悩み → 用途 → 技法 → 制作事例

### 余白映像研究所
違和感 → 現象 → 認知 → 実験 → 研究テーマ

### SRI / JSSI
社会的違和感 → 構造問題 → 分析対象 → 研究・論文

### 商品探索
曖昧な欲求 → 用途 → カテゴリ → 条件 → 商品

### AI検索
曖昧な不足 → AIによる不足構造推定 → 候補生成 → 比較 → 対象確定

## 10. SEOとの違い

一般的SEO:

```
検索語
→ 検索意図分類
→ コンテンツ最適化
```

不足探索モデル:

```
未言語の不足
→ 欲求
→ 行動目的
→ カテゴリ
→ 対象
→ 条件
→ 固有対象
→ 検索語
```

したがってDSTはSEOキーワードツリーそのものではなく、
**検索語が生成される前段の認知構造まで扱う上位モデル**
として位置付ける。

---

## 11. 用語

- モデル: **Deficit Search Model / 不足探索モデル**
- 構造: **Deficit Search Tree (DST) / 不足探索ツリー**
- 実装系: **Deficit Exploration Engine (DEE) / 不足探索エンジン**

---

## 12. AI実装の基本原則

AIには単に「関連キーワードを出せ」と指示しない。

基本プロンプト思想:

```
入力語・実績語から、
1. 背景にある不足を推定
2. 探索レベルを分類
3. 上位・横・下位の3方向へ展開
4. 実測データがある語を観測済みノードとして優先
5. 推測ノードと観測済みノードを区別
6. 次のコンテンツ候補へ変換
7. 公開後データでツリーを再学習・更新
```

---

## 13. 中核命題

> 人は検索語を探しているのではない。  
> 自分の中の不足を、対象へ変換しながら探索している。

コンテンツは、その探索途中に置かれる「不足充足候補」である。

したがって、ストック型コンテンツとは、
**特定の不足探索経路上に継続して置かれ続けるコンテンツ**
と定義できる。
